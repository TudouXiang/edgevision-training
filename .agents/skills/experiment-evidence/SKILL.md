# 实验与验收证据

## 触发条件

准备或记录数据校验、训练、ONNX/推理、性能与硬件实验，或声称某条验收通过时。

## 输入

任务/实验 ID、授权预算、代码与未提交差异指纹、数据/权重来源与哈希、Job/Artifact ID、环境/硬件/provider、预设阈值和原始日志；无真实资产或权限不启动实验。

## 步骤

1. 运行前确定测量对象、指标单位、阈值、软件版本、随机种子和设备；不得事后改阈值冒充通过。
2. 记录开始/结束时间、原始命令与退出码、原始文件路径及 SHA-256；训练记录 epoch/metrics/checkpoint；ONNX 验证记录载入、输出一致性、真实图片推理。
3. 如无设备或计算环境，明确写「未执行」，不从截图、模拟结果或 CPU 推断 RKNN/NPU 性能。
4. 先区分整理现有记录、最小烟测与正式实验。性能对比先对齐数据划分、类别、预处理、阈值、NMS、warm-up、计时分段与线程；部署包须离开平台环境实跑。原始证据只增补，更正需追溯旧版。

## 输出

`docs/evidence/` 下每实验一份记录：输入指纹、预设阈值、实测值、证据路径、通过/失败/未执行与复现实验步骤。使用 [证据模板](references/output-template.md)。

## 停止条件

输入来源/哈希缺失、实际命令或原始日志缺失、设备身份未知、没有预设阈值、结果可能来自测试替身或超出授权预算。标为未验收并指出补证方法。[行为用例](references/eval-cases.md) 不是模型实验。
