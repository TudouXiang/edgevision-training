# 单任务交付

## 触发条件

接到 `docs/tasks/` 中一个已放行的任务 ID 或需要修复该任务的一项失败验收；任务文件存在本身不代表前置已满足。

## 输入

明确的任务 ID 与验收项、`AGENTS.md`、`docs/status.md`、相关 `docs/contracts.md`/架构/表/存储规范、实际源码与测试、`git status --short`。

## 步骤

1. 只实现任务单对应的纵向切片；先核对表迁移、权限、错误分支和已有可复用代码。
2. 所有业务响应取自真实数据库/文件/执行结果。测试数据仅在测试环境注入，不能进入正式启动链路。
3. 对成功、权限拒绝、校验失败、取消或失败恢复做必要测试；运行能执行的命令并如实记录未执行项。
4. 保留 API 与后端 Pydantic/OpenAPI 生成的前端类型一致；生成文件不得手改，检查无类型漂移。更新 `docs/status.md` 和 `docs/evidence/` 中的实际证据。
5. 审查完整差异，排除密钥/数据/模型、无关格式化或调试文件；未放行下一阶段不得顺带实现。交付先标 review_required。

## 输出

变更文件清单、契约差异、实际命令及退出码、失败/边界用例结果、任务验收项逐条结论、后续阻塞项。使用 [交付模板](references/output-template.md)。

## 停止条件

任务依赖尚未具备；需修改产品范围或核心状态/接口却尚未执行 `arch-spec`；需要未授权系统安装/付费/长时间训练；需要覆盖他人的未提交修改。先交付已完成的独立部分和阻塞原因。[行为用例](references/eval-cases.md) 尚需宿主验证。
