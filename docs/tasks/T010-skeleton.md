# T010：可启动骨架与精确契约

执行者：GPT6/Codex。前置：T000 实际盘点；用户授权在目标仓库内搭建骨架。状态：**accepted**（Windows A01–A04 PASS，见 `docs/evidence/T010-review-2026-09-29.md`；独立 change-review 为 `accept`，见 `docs/evidence/T010-change-review-2026-09-29.md`）。T020 已为 ready，本轮未领取。此前 Linux 未通过项仍见 `docs/evidence/foundation-report.md`。

## 目标

交付能启动、能生成契约、能跑基础测试的最小工程，让实现模型不再自行决定公共边界。不是实现全部业务。

## 允许修改

前后端工程配置、基础目录/入口、Schema、数据库模型及初始迁移、状态转换基础、ML适配协议、测试基础、开发脚本与文档。既有架构优先复用。

## 必须完成

1. 轻量 API入口、配置/错误处理、live/ready/capabilities；缺ML依赖不阻止轻量启动。
2. User/Session/Project/Dataset/Job/Artifact持久化结构和初始迁移；明确约束、索引、资源关联、时间和JSON字段版本。不得只留六个空类。
3. 所有首版请求/响应DTO与Job参数Schema：字段、类型、必填/可空、范围、枚举、错误码、分页、日志游标。T000已知环境决定参数/资源上限，不长期留“以后再定”。
4. 状态转换集中定义与测试；取消/成功竞争及恢复规则的实现设计。Worker此轮只提供可检查的入口和协议，不实现完整训练执行。
5. Pydantic生成OpenAPI及前端类型，提供可重复生成和漂移检查入口。
6. 最小前端壳、路由、统一请求/错误、真实健康状态和诚实空态。未实现接口明确501或对应不可用错误。
7. 统一环境检查、前后端启动、迁移、基础检查、契约生成命令，记录实际可用调用。命令应避免无关系统修改和默认长训练。
8. 针对配置缺失、临时数据库迁移、枚举/参数校验、非法状态转换、未实现路径、契约生成的真实测试。Fake只在测试注入。

## 不做

不实现完整登录业务、数据上传处理、正式任务消费/训练/导出、复杂仪表盘、RKNN、远程部署、论文结果。不给“下一步顺便把剩下全做完”的自动授权。

## 验收

执行A01-A04；基础测试实际运行，前端构建通过且浏览器核验最小壳。浏览器环境不可用记NOT_RUN，不能宣称完全验收。隔离环境内迁移/类型生成可重复运行，未实现路径不会误报成功。

输出 docs/evidence/foundation-report.md 及本机补证报告，记命令、退出码、版本/工作区指纹、产物、失败/未执行、阻塞与 T020 可领取条件；更新 status。实现完成先停在 review_required，由独立审查放行；本次审查已通过，仍不在同一轮进入 T020。
