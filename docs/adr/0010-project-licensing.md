# ADR 0010：项目许可与第三方边界

- 日期：2026-11-04 UTC
- 状态：accepted（项目许可选择）；第三方发行包与 T050 资产许可核验仍有未完成项
- 代码基线：`3795759`，`feat/t040-worker-validation`

## 问题与事实

项目此前没有根 LICENSE；T050 仍需可信资产、目标 ML 环境与许可核验。项目所有者已明确
委托决定许可证等实现选择。原技术路线是 YOLO11n / Ultralytics；其官方仓库提供 AGPL v3，
官方许可页列出 AGPL 与 Enterprise 两条路线。当前锁文件未引入 ML 组件，不能把计划写成
已安装或已验证。旧参考 ZIP 没有可确认的整体许可，权重和数据集也没有因仓库命名而获得授权。

## 决定与最小方案

对有权授权的项目原创源码、脚本、测试、配置、项目自有生成契约及文档采用
**AGPL-3.0-only**，完整原文放入根 `LICENSE`。由 `LICENSE_SCOPE.md` 明确版本与排除项，
`THIRD_PARTY_NOTICES.md` 记录当前依赖和未来 ML 核验要求。保留第三方原许可及归属，
不声称拥有参考包、第三方代码、图标、数据或模型权重。

理由：与已选择的 Ultralytics 开源路线保持一致，并在网络应用场景明确对应源码义务。
不购买商业许可、不签署额外协议，也不因此提前放行 T050 或改动产品范围。

比较过的方案：仅继续保持“未选择许可证”改动最少，但不能给项目原创部分清楚的复用条款；
对原创部分采用 MIT 并保留各依赖许可是另一种分层方案，但不能解除未来 Ultralytics
组合使用的 AGPL 义务，且会增加交付说明复杂度。本次选择明确的 AGPL 路线，未选择付费或
闭源路线，也未为未知素材推断任何新授权。

## 影响、迁移与后续变更

- 无 API、数据库、进程、权限、依赖版本或运行模式变更，无数据迁移。
- 本次不修改依赖包、不导入/执行参考 ZIP、不下载数据或模型、不训练、不部署。
- 发行包仍需以实际包含的精确版本收集所有适用 LICENSE/NOTICE 与对应源码；未来公开运行
  修改版本时按 AGPL 第 13 节落实显著、可用且匹配版本的源码获取入口。本次没有 UI 改动。
- 后续可在有权决定的范围内更改未来原创代码的许可；已经在 AGPL 下授出的副本权限不能
  靠删除或替换 LICENSE 单方面撤销，仍依 AGPL 第 2、8、10 节等条件处理。其他贡献者和
  第三方权利不受项目文件替换影响。因此“回退文档”不等于撤回已生效的许可。

## 剩余闸门与验证

T050 的权重/数据来源与精确许可、目标 ML 环境、锁定依赖及真实小规模训练仍待完成；
T060 部署包的第三方通知与源码交付须单独验收。参考包保持排除和不投产状态，若将来复用
须先确认原型与各资产权利。发现未知来源文件时先隔离核验，不用根 LICENSE 补造来源。

核验见 [许可证据](../evidence/licensing-2026-11-04.md)。手动读取并执行项目 `arch-spec`
流程；这不宣称 Skill 自动触发成功。未重新运行应用测试，因本次仅新增和更新许可文档。
