# ADR 0003：持久事件 + SSE 续传

状态：历史决策；2026-09-23 的 ADR 0005 针对 V1 日志协议改为有界轮询。本 ADR 留供差异追溯，当前实现按 ADR 0005。

决策：Worker 将状态、日志、指标持久写入 SQLite；浏览器先 GET 当前 job，再以 SSE `Last-Event-ID` 续传，断连可退化为定期 GET。SSE 的 `seq` 单 job 递增并去重，权限每次请求重新验证。

理由：单机任务只需服务端到浏览器的单向事件流；原演示版文案声称 WebSocket 更新但实际上用计时器制造变化。优先建立可回放、可重连的真实来源，无需双向通道。影响：未来旧原型的 WebSocket 状态提示必须改为真实 SSE/轮询状态；若出现双向实时控制需求，需单独评估协议，不据此引入新调度设施。
