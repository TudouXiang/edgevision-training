# ADR 0012：T060 重建前的隐私与执行边界

日期：2026-11-04 UTC。状态：安全准备实现待审查；导出/推理/部署尚未重建。

## 基线与问题

基于已公开 T050 的 3b5b8ec。此前未发布的 T060 源文件和执行产物不可取得，不能把历史测试计数当作新代码证据。旧版本环境重建会清空全部继承变量；仅在 launcher 设置原生库遥测关闭不足以覆盖随后导入。

Python 审计钩子不是原生网络沙箱。固定 ORT 官方源码表明，遥测 SDK 在 Python 模块导入期间就可能初始化；之后调用禁用事件 API 不等于销毁已有上传器或清空队列。参考固定源提交 [环境 opt-out 语义](https://github.com/microsoft/onnxruntime/blob/6af1a932e2286d5c58166085d24c68783033edee/onnxruntime/core/platform/telemetry_environment.h)、[原生初始化](https://github.com/microsoft/onnxruntime/blob/6af1a932e2286d5c58166085d24c68783033edee/onnxruntime/core/platform/telemetry_1ds.cc)。

## 最小兼容决定

1. 所有受管 Python 子进程在解释器启动前，使用独立环境副本强制设置 `ORT_DISABLE_TELEMETRY=1`，不修改父进程环境。
2. 训练环境清理后、任何 ML 导入前再次设置并检查初始化顺序。拒绝未经该保护而已加载的 ORT 或其子模块。
3. 后续 ORT 适配器必须通过单一加载函数；先用发行元数据确认规划的1.31.1版本，再导入并附加调用官方禁用事件 API。现在没有安装/导入该运行时，函数存在不代表导出能力可用。
4. 将隐私模块和启动器纳入现有运行指纹。旧探针记录过期是预期行为，不沿用旧能力状态。
5. 重建分支的真实 ML CI 暂停，不在普通push恢复执行。先设计受审查的、非特权且禁止外部网络的容器边界，再决定是否允许显式运行。不把改环境当作绕过执行限制。

替代方案“只在 ORT 导入后调用禁用 API”时序太晚，因此不采用。关闭遥测也不能替代内核网络隔离；本轮只运行不导入 ML 的单元和轻量回归。

## 兼容与回退

不改数据库、公共 DTO 或任务状态。CPU训练输入/输出规范不变，但源码绑定更新后必须在安全条件具备时重新做实际探针。回退只退代码，不能伪造或改写能力记录；历史产物和数据保留。

## 下一阶段闸门

本决定仅处理重建准备。E 导出仍需新冻结的工具链、严格元数据、checker/实际ORT执行、真实数值比较、退出确认和原子发布；I/P分别需要真实图片处理及独立环境验证。所有新运行结果必须重新生成，未执行项明确标记 NOT_RUN。
