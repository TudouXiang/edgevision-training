# ADR 0001：单机持久化和单重任务调度

状态：已接受，2026-09-23。

决策：FastAPI 单服务 + SQLite 元数据 + 本地文件，独立单实例 Worker + 每 job 子进程，global heavy task 串行。DB 短事务领取和中断恢复，持久 job events；无 Redis/Celery/微服务。

理由：毕设首版需要清晰、可测试、可部署的真实训练链路，单机资源受限，分布式调度对验收无收益。影响：不能横向扩容或并发训练；Web 只能排队并显示真实状态。更小的替代是把训练放 API BackgroundTasks，但进程重启和生命周期不可控，因此不采纳。后续变更必须迁移 job 语义和 DB，不能简单在 API 内增加并发。
