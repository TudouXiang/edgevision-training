# ADR 0005：启动包与既有骨架对齐

状态：T010 候选，待审查；2026-09-23。依据：用户提供的 `edgevision-foundation(1).zip`、现有提交 `57920e6` 及仓库比对。

## 问题与决定

用户授权仅 T000/T010。包内公共契约相对现有骨架变更了日志协议、状态名、若干 URL 与验收编号。保留前端设计、现有 npm/Vite 工程、SQLite `0001_initial` 和真实健康接口；新增 `0002_foundation` 迁移、统一 Python Enum/Pydantic DTO、OpenAPI/TS 生成入口与 T000/T010 测试。已执行过的 `0001` 不编辑；升级既有数据库前须停服务、做一致性备份、先在副本验证。

| 冲突 | 最小调整 | 影响与验证 |
| --- | --- | --- |
| 旧 ADR 0003 SSE/手写 TS | V1 改为有界增量轮询；Pydantic/OpenAPI 为唯一公共源，现有 TS 仅前端健康接口临时桥接 | 无已实现 SSE 消费者；新增生成/漂移检查，真实生成未运行前 A03 不通过；本 ADR 覆盖 0003 的 V1 协议选择，不删除其历史 |
| 旧 Worker 重启直接 `failed/INTERRUPTED` | `interrupted` 单独终态；不明遗留进程先停领待人工核对 | 保留运行/取消证据，防止双任务并行；T040 才实现受管进程核对自动恢复 |
| 旧数据集、job kind、artifact 验证枚举 | 两阶段兼容迁移映射，增加新列 | 老用户记录需迁移；本执行容器缺 Python 依赖，迁移**未实跑**，审查前不得用于用户正式 DB |
| 包默认 pnpm、新建前端 | 继续复用已有 Vue/npm 和视觉设计 | `npm ci` 与 Vite 构建、路由验证；无收益时不替换锁文件体系 |
| 包要求 PT 与 ONNX 均可真实图片推理 | 接受用户此次提供包的范围补充，仍以 ONNX 部署主线 | 实现推迟 T060，分别记录真实 backend/provider；不把 PT 冒充 ONNX |
| 原 2 GiB 上传上限 | T010 默认为 512 MiB，解压上限 2 GiB，任务参数有保守范围 | 当前容器 30 GiB 空闲但不是用户开发机；正式容量与时长需在目标机复核，使用配置收紧，不接受不受限输入 |

## 没有采纳的方案

重写前端为另一个包管理器、保留 SSE 并增加轮询双轨、修改旧迁移或把旧中断标记直接重写为新终态，会增加协议/数据风险。历史 T0–T9 草案留在 `docs/tasks/legacy-tasks.md`，当前入口为 T000–T070。现有模型元数据规范继续沿用并按新字段对齐。

## 未验证与回退

本容器缺 FastAPI/SQLAlchemy/Alembic/pytest；无法完成临时库真实升级、OpenAPI 导出、生成 TS 与 API 调用。审查仅可批准或要求修改此候选，不能据静态语法检查升级用户已有库。回退新代码可恢复 `57920e6`；已执行的 `0002` 不能未经单独数据检查降级，迁移故意禁止静默 downgrade。学校是否强制 NPU 实机须由用户与导师核对。
