# V1 范围冻结

## 目标与用户

本机运行的双角色 Web 平台；普通用户管理自己的数据，管理员管理账号、所有项目及全局任务。服务端以会话角色和 owner_id 校验权限，不信任前端角色切换。模型任务限 **目标检测**，推荐起点 YOLO11n/Ultralytics；只接受受控的 YOLO 格式 ZIP 数据集。

主流程：登录 → 项目 → 数据集导入/校验/有限预览 → 参数化训练 → 日志/指标 → PT 模型 → ONNX 导出及加载验证 → 真实图片推理 → 包含已验证 ONNX 模型和示例的部署包下载。

## 必须交付的 V1 能力

账号初始化和登录/退出/改密、双角色授权；项目创建/查看/编辑/归档；不可变数据集快照、校验报告与有限图片/标注预览；训练任务创建/取消/恢复终态；日志、指标、基础实验对比；best/last 模型及元数据；ONNX 导出与验证、单张图片真实推理及留档；可复现部署包与下载。PT 与 ONNX 推理均需真实执行，且记录实际后端，ONNX 作为部署主线。成功态必须有真实输出文件与记录指纹；不接受任意外部 PT。

## 明确排除

用户自助注册、在线标注、其它视觉任务、任意模型格式互转、并发多重任务/分布式/多 GPU 调度、暂停与恢复训练、视频/摄像头流、远程设备连接、设备管理和 NPU 实测、模型市场、会员/付费功能。RKNN 只冻结 `target_format` 扩展枚举/转换适配器接口与元数据字段；没有 RKNN Toolkit 和实机证据时不得提供可点击的“RKNN 成功”流程。

重新训练创建新 Job，不复活已终结任务。项目归档保留历史；首版磁盘不足拒绝新写入，不擅自物理清除用户数据。YOLO11s 仅在完成工具链核验且确有对比需求后考虑，不自动扩大模型组合。

## 验收边界

论文、可视化或原型效果不能替代真实链路；拆分验收见 `acceptance.md`。过去较宽的设备、视频、三语言代码生成等构想不进入 V1。更改范围必须先经 `arch-spec` 给出影响和最小调整。

正式题名、学校硬性要求和边缘设备验收尚未由本仓库核对；若题目承诺实机 NPU/边缘部署，必须另行确定目标板与验收，不能将工具链设计写作实测通过。代号 EdgeVision 不是正式毕设题目。
